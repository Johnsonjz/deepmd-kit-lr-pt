# 全线 AD：把 ik 从代码里去掉

目标：**力的微分方式在两条链、所有后端上统一为 AD（权重微分 = 精确 `−∇E_mesh`）**，
不再保留 ik 梯度场。

---

## 0. 现状盘点

| 位置 | 力的微分 | 状态 |
|---|---|---|
| lr-pt 图内算子 · B-spline（`mesh_sum.cu`） | AD（`slope` 张量积缩并） | ✅ |
| lr-pt 图内算子 · midtown（`sog_gpu.cu`） | AD（`cs2_wg6`） | ✅ |
| lr-pt CPU/参考（`kernels/long_range.py`） | AD（完整 autograd） | ✅ |
| LR LAMMPS · CubeS₂ / QuadS | AD（adjoint，1 次逆变换） | ✅ |
| **LR LAMMPS · B-spline** | **ik**（3 个梯度场 + 3 次 BACKWARD） | ← **唯一要改的** |
| LR LAMMPS GPU（`sog_gpu.cu`） | 只实现 CubeS₂/QuadS | ← **有缺陷**，见 §1.3 |

所以工作量几乎全在 `../deepmd-kit-LR/source/lmp/sog.cpp` 的一个分支里。

---

## 1. 为什么改

### 1.1 力必须是 `−∇E_mesh`
ik 算的不是网格能量的梯度，而是"精确势场采样后插值"的梯度。后果：
- 力与能量不自洽；
- `Σ F·r` 与模求和 virial 不自洽（现在靠各自的经验修正掩盖）；
- NVE 有系统性漂移（靠恒温器掩盖）。

AD 是精确梯度：`dE/dx_i = q_i (∂w_i/∂x_i)ᵀ φ_mesh`（spread 与 gather 两半在 `G`
对称下相等，见 [MIDTOWN_AD_DESIGN.md](MIDTOWN_AD_DESIGN.md) §2），
所以能量/力/维里三者天然一致。

### 1.2 两棵树各用一套，"交叉验证"就是自欺
现在用 LAMMPS 交叉验证 lr-pt 的 B-spline，验的是 **ik 对 AD**，
差里混着微分方式与去卷积实现两个效应。统一之后这项验证才有意义。

### 1.3 顺带修一个静默错误
`enable_gpu yes` + `spline bspline_*` 时，`sog.cpp:1974` 把 `spline = 0` 传给
`sog_gpu_compute()`，而后者**只认 CubeS₂/QuadS**：

```cpp
bool quads = (spline==SOG_QUADS_4||spline==SOG_QUADS_6);
int  nord  = (spline==SOG_CUBES2_6||spline==SOG_QUADS_6)?6:4;   // spline=0 -> 4
```

`spline=0` 既不是 QuadS 也不是 CubeS₂-6 → **静默按 CubeS₂-4 的模板跑**，
而绿表是按 sinc/B-spline 建的。默认 `enable_gpu=false`（`sog.h:93`），
所以只有显式开 GPU 才触发，但一旦触发就是**错误结果而非报错**。

## 2. 代价（必须先摊开）

AD 比 ik **少约一阶**（ik 的力指数≈样条阶，AD 的力指数≈阶−1.3）。
同网格下 B-spline-6 的力误差大约放大 **3×**（`Δ/σ=0.4` 量级，**按同样的 `C`、指数 7.3 vs 6.0 估算**：ik ≈4e-5 → AD ≈1.4e-4；真实 `C_ik` 要用 §3.1 实测）。

但是：

> **发布的 `FORCE_RULE` 本来就是按 AD 标定的。**
> `grid_rule.py` 的 `("bspline",6): (3.34e-2, 6.0)` 是在 lr-pt 的 **AD** 实现上量的。
> 也就是说现状是"LR 用 ik、却套 AD 的常数"——**一直在过度分辨**。
> 换成 AD 之后，规则与实现对齐，**不需要改规则，出图也不变**。

若要把掉的那点精度补回来：`Δ` 细 `3^(1/6.5) ≈ 1.18×`，即格点 `1.65×`。
这个数要先用 §3.1 的实测确认，再决定是否调规则。

## 3. 实现（LR 侧）

### 3.1 先量，再改 —— **已完成**

`docs/measure_ik_vs_ad_force.py`：同一个网格管线里同时实现 AD 与 ik，
所以两者的差别只剩下微分方式本身。**AD 分支先与现有算子对齐**：

```
energy  proto -7.946478815  op -7.946484106   rel 6.7e-07
force   rms(proto-op)/rms(op) = 2.1e-07
```

结果（B-spline，σ_min = 2.00 Å，32 个 64 原子构型，直接 k-sum 参考，
横坐标 `Δ = L/n` 真实间距）：

| 阶 | scheme | `p_F` | `C_F` | R² | `Δ/σ` @1e-4 力 |
|---|---|---|---|---|---|
| 4 | AD | 3.40 | 7.63e-2 | 0.9981 | 0.1419 |
| 4 | ik | 4.37 | 5.10e-2 | 0.9986 | 0.2402 |
| 6 | AD | 6.36 | 3.52e-2 | 0.9985 | 0.3979 |
| 6 | ik | 7.40 | 2.83e-2 | 0.9979 | 0.4663 |

**ik 恰好高一个阶**（4 阶 3.40→4.37，6 阶 6.36→7.40），与"对 `C⁰` 窗口求导掉一阶"
一致。等 1e-4 精度下：**AD 需要 1.61×（6 阶）/ 4.84×（4 阶）的格点**。

同时**独立复核了已发布的 `FORCE_RULE`**：手册里的 `bspline-6 = (3.34e-2, 6.0)`、
`bspline-4 = (1.17e-1, 3.5)`，实测 AD 是 `(3.52e-2, 6.36)`、`(7.63e-2, 3.40)`——
指数吻合，常数略小（规则偏保守 1.05–1.5×），方向安全。

**换算到实际口径**：发布网格是按 AD 标定的，所以在**出图网格不变**的前提下，
从 ik 换到 AD 会让力误差从 `3.1e-5 / 1.0e-5`（6 阶 / 4 阶）落到 `1.0e-4 / 1.0e-4`——
**正好落在目标上**（现状是过度分辨 3.2× / 10×）。

### 3.1b 决策

实测把代价钉死了：

| 看法 | 结论 |
|---|---|
| **按出图网格**（规则按 AD 标定，不变） | ik→AD 后力误差从 3.1e-5(6 阶)/1.0e-5(4 阶) 变成 1.0e-4/1.0e-4，**正好落在目标上**；现状是过度分辨 3.2×/10× |
| **按同等精度** | AD 要多 1.61×（6 阶）/4.84×（4 阶）格点 |

所以"换成 AD"在两处都不吃亏：出图上不用改，精度回到标称值而不是超配；
性能上还省两次逆变换。**建议按原计划推进**，并且**顺带把网格规则的常数收紧**
（实测 `C_F` 比手册小 1.05–1.5×）——这是纯赚，但属于另一件事，先记在 §5。

### 3.2 权重导数 —— **已实现并验证**

`sog_bspline_weights_1d_order_d`：不套 `M_p'(x)=M_{p-1}(x)−M_{p-1}(x−1)`
（那条要手工映射下标，错一位就是静默错力），而是**把原递推整体对 `frac` 求导**——
每一行都是 `frac` 的线性式，导数递推逐行对应，**下标约定自动一致**。

验证：[docs/bspline_ad_reference.cpp](bspline_ad_reference.cpp) 独立编译，
与 torch autograd 比（[check_bspline_ad_reference.py](check_bspline_ad_reference.py)）：

```
n=2..8    max|w_cpp − w_torch| = 0        max|dw_cpp − dw_torch| ≤ 3.3e-16
```

### 3.2b 索引约定：两棵树差一个平移

`sog.cpp` 把模板定在 `floor(u) − (p−1)/2`，`mesh_sum.cu` 定在 `floor(u) − p + 1`，
**权重数组逐位相同**，只是电荷网格整体平移 `(p−1)/2` 个格点。收/散用同一个平移，
所以物理结果不变（实测：把 LR 的网格 `roll` −3 后与 `mesh_sum` 的网格差 1.1e-15）。
记录这一点是因为**两个网格数组不能直接比**，只能比力。

### 3.3 力收集改成 AD —— **已实现并验证**
把 `sog.cpp:2457-2515` 的权重-only 缩并换成
**值 × 3 个斜率**的张量积缩并（结构与 `mesh_sum.cu:765-802` 的 `interpolate_owners`
逐行对应）：

```
φ   = Σ_{abc} wx[a]wy[b]wz[c] · u[idx]
∂φ/∂x = Σ (dwx[a])wy[b]wz[c] · u[idx]      （y、z 同理）
F_i = −q_i · ∂φ/∂x
```

斜率的坐标系换算：`∂φ/∂x_d = (∂φ/∂u_d)·n_d/L_d`。

验证：把 `bspline_ad_force()` 写成独立可编译的参考实现，喂给它 Python 原型生成的
**同一张势场网格**，与原型（自身已与发布算子对齐到 2.1e-7）比对：

```
order 6, n=12, N=64:  max|F_cpp − F_prototype| / max|F| = 8.7e-16
```

推导过程中确认了三件事（都写进了参考实现的注释）：
网格是 `ix + nx*(iy+ny*iz)`（x 最快），tensor 是 `[ix,iy,iz]`（z 最快）必须转置；
`qscale` 与 COUL 只能出现一次（LR 的绿表不含 COUL，原型的 influence 含）。

### 3.3b 已落地到 `../deepmd-kit-LR/source/lmp/sog.cpp`

| 改动 | 位置 |
|---|---|
| 新增 `sog_bspline_weights_1d_order_d` | `sog.cpp`（紧接原权重函数之后） |
| B-spline 收集改 AD（值 × 斜率张量积） | `sog.cpp` 的 `spline_type < 4` 分支 |
| 删除 `mesh_gradx/y/z` 的构造、3 次 BACKWARD、3 个缓冲（`sog.h` 成员一并删） | 多处 |
| `mesh_pot` 从「仅 `want_potential`」改为**总是**构建 | k 空间循环 + 逆变换 |
| `use_gpu yes` + `spline bspline_*` 改为**显式报错** | GPU 分支入口（§3.6 第一步） |

**验证状态**：

- 数值：§3.2 / §3.3 的独立参考实现已与验证过的原型对齐到 `1e-16`；
- 编译：本机没有该树可用的 LAMMPS 构建，用 `lammps_src` 做 `g++ -fsyntax-only`，
  **4 个报错全部是 LAMMPS `FFT3d`/`Remap` 构造函数的 API 版本不匹配**
  （该树针对的 LAMMPS 比手头的新），**没有一个是本次改动引起的**；
- **尚未运行**：需要一棵匹配版本的 LAMMPS 来构建插件并跑 §4 的验收。

（已随 §3.3b 一起完成。）净变换数：`want_potential` 时 `4 → 1`，
否则 `3 → 1`；省下的显存是 `3 × 2 × ngrid × sizeof(FFT_SCALAR)`。

### 3.5 virial 不动
`fv_local` 的模求和（`geff_energy − gv·k_a k_b`）本来就与力的微分方式无关。
换 AD 后新增一条**更严格**的自洽检验：`Σ F_i ⊗ r_i` 应当与模和 virial
在离散误差内相等（ik 时这是不成立的）。

### 3.6 GPU 分支（0.2 d 修错 + 2 d 补实现，可分两步）
- **立刻**：`sog.cpp:1974` 前加护栏 —— `enable_gpu && spline_type < 4` 直接
  `error->all(FLERR, "...")`，把静默错误变成显式拒绝。
- **之后**：若要 B-spline 上 GPU，照 `sog_gpu.cu` 现有的 CubeS₂ gather 结构加一个
  B-spline AD gather。**不建议现在做**：lr-pt 侧已证明 gather 不是瓶颈，
  而 GPU 收益主要在 FFT 与原子加。

### 3.7 与 midtown AD 重构的关系
[MIDTOWN_AD_DESIGN.md](MIDTOWN_AD_DESIGN.md) 是**性能/结构**改造，与本计划正交，
但方向一致：两者都让"逐原子一维表 + 无分支缩并"成为统一形状。
建议顺序：**先做本计划的 §3.1–3.5（正确性），再做 midtown 重构（性能）**。

## 4. 验收

1. **自洽**：`F = −∇E_mesh`。用能量中心差分核对（`h=1e-4 Å`），
   `rms(F − F_fd)/rms(F) < 1e-3`。
2. **virial**：`Σ F⊗r` 与模和 virial 的差值 < 离散误差（换 AD 前这一项是 1e-2 量级）。
3. **NVE**：10 ps 能量漂移，ik vs AD 对比，AD 应显著更小（预期 ≥10×）。
4. **跨树**：同核、同盒、同网格下 LR 的 AD 力 vs lr-pt 的 AD 力，
   残差应当只剩**去卷积实现差异**（LR 截断 sinc 混叠和 vs lr-pt 精确 `1/|D|²`）。
   → 这一步会顺带决定要不要把 LR 的 sinc 截断也换成精确除法（**建议换**，
   否则跨树仍不可逐位对齐）。
5. **性能**：nsys 对比每步时间，确认省下 2 次逆变换。
6. **回归**：LR 侧现有 SOG 相关测试；lr-pt 侧 `test_long_range_sum.py` 等不受影响。

## 6. 风险

- **精度回退**：同网格下 B-spline 力误差约 3×。缓解：规则本就按 AD 标定，
  出图不变；若要补精度，格点 1.65×（§2）。
- **性能**：gather 的算术从 `n³×1` 变成 `n³×4`（order 6 即 `216×1 → 216×4`），但在 250³/196608 的实测里
  gather 是访存受限、算术不是瓶颈，预期净变化为**省 2 次逆变换**（约 −0.55 ms）。
  需要在 §4.5 里确认，而不是假设。
- **不要半途而废**：AD 与 ik 混用比统一用任何一个都糟（无法解释力/维里的残差）。
  若 §3.1 显示精度损失不可接受，就**停在 Phase 1**、保持现状并在文档里写明
  "两条链的 B-spline 微分方式不同"，不要只改一半。
