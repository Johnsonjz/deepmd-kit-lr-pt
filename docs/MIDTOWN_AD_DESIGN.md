# midtown spline 的 AD 力实现：重构设计（参照 B-spline）

> **范围先说清楚**：这是一次**结构/性能**重构，**不改变精度**。
> 力的离散化仍是 `∇E_mesh`，`p_F = p_E − 1` 的结论不变。
> 要改精度只能换微分方式（ik），那是另一份计划
> （[FORCE_DIFFERENTIATION_PLAN.md](FORCE_DIFFERENTIATION_PLAN.md)）。
> 本设计的目标是：把 midtown 的 AD 路径改造成**与 B-spline 同构的三段式**，
> 消除逐节点的类别发散，并让 ik 改造有一个干净的落点。

---

## 1. 参考：B-spline AD 的三段式

| 阶段 | kernel | 结构 | 为什么这样做 |
|---|---|---|---|
| ① 逐原子元数据 | `node_stencils<kOrder>` | 一线程一 (node, axis)，fp64 递推出 `value[p]`/`slope[p]`/`offset[p]` | fp64 指令无论 lane 是否活跃都占满 fp64 流水线，所以把 fp64 工作放在"所有 lane 都在干活"的稠密 kernel 里 |
| ② 散布 | `spread_charges<kOrder>` | 一 warp 一原子，`LaneSlots` 把 p³ 模板摊到 32 lane，lane 负责连续的 x 段 | 让一条 warp 的访存落在连续地址上；定点 int64 原子加保证可复现 |
| ③ 收集 | `interpolate_owners<kOrder>` | 一 warp 一原子，读 φ 网格 + 用 `value`/`slope` 做**张量积缩并** | 内层循环**无分支**：`φ = Σ v1v2v3·φ`，`∂φ = Σ (s1v2v3, v1s2v3, v1v2s3)·φ` |

三条可迁移的架构性质：

1. **逐原子元数据先算、单独算、稠密算**；
2. **lane → 模板的映射让访存连续**（x 方向成段）；
3. **缩并段无分支**——张量积的可分离性把"每个节点一次多项式"降成"每轴 p 个数一次"。

## 2. 当前 midtown AD 与它的差距

`k_gather_cubes2_warp_r`（`midtown/sog_gpu.cu`）逐节点调用 `cs2_wg6`：

```c
if (nd.cls == 0) { ... 4 项 ... }            // 30+ FLOP，gL111/gS6 反向模式
else if (nd.cls == 1 || nd.cls == 2) { ... } // 又一套
else if (nd.cls == 3) { ... }
else { ... }                                  // cls 4
```

一条 warp 的 32 个 lane 持有 32 个**不同**节点，`cls` 各不相同 →
**分支在整个 warp 内发散：每条 lane 实际执行全部 5 个分支**。

这就是"没有可分离性"的真正代价：B-spline 用 36 个一维值支撑 216 个节点，
CubeS₂ 直接在 88 个节点上各算一遍，且每次都要跨过一个 5 路分支。

已测（RTX 4090，N=196608，250³）：gather 0.71 ms / 3.14 ms = 23%；
其中算术不是主因（把 `gL/gR/gL111/...` 从 fp64 改 fp32 收益 ≈0，
把 fp64 分数坐标提到独立 kernel 才有 −28%）。**所以本设计的收益来自"去分支"，
不来自"少算"。**

## 3. 关键观察：每一类都是 **≤4 项一维函数之积的和**

逐类核对 `cs2_w6_tab`（`sog_gpu.cu`）：

| cls | 表达式 | 项数 |
|---|---|---|
| 0 | `L111_x·ey·ez + L111_y·ez·ex + L111_z·ex·ey + S6x·S6y·S6z` | 4 |
| 1 | `L211_sp·eta_n1·eta_n2 + R_sp·S6eta_n1·S6eta_n2` | 2 |
| 2 | `L311_sp·eta_n1·eta_n2` | 1 |
| 3 | `S6eta_nm·R_s1·R_s2` | 1 |
| 4 | `R_x·R_y·R_z` | 1 |

**每一项都是 `A(x)·B(y)·C(z)`**，缺的轴补常数 1。这就是 CubeS₂ 版的"可分离性"：
不是严格可分离，但**是可分离项之和**，项数 ≤4 且对所有节点统一。

于是可以引入**通用四项式**：

```
w_n = Σ_{t=0..3}  A_t(x)·B_t(y)·C_t(z)

∂w_n/∂x = Σ_t  A'_t(x)·B_t(y)·C_t(z)      （y、z 同理）
```

没有任何类别分支——`cls` 只在**离线**用来生成索引表。

## 4. 设计

> **状态**：§3 的"≤4 项一维之积"已用 Python 参考实现验证——
> 120 个节点（4 阶 32 + 6 阶 88）× 50 组随机 `(tx,ty,tz)` × 32 个点，
> **值与三个梯度的最大偏差 1.1e-16**。

### 4.1 基函数基（6 阶 7 种）

一维基只需 7 种，且 `eta`/`S6eta` 折叠成"`elt`/`S6` 取反"的下标：

| kind | 值 | 备注 |
|---|---|---|
| 0 | `0` | **零基**：未使用的项 |
| 1 | `elt(e)` = `e ? 1−t : t` | 同时充当 `eta[i]`（`e = (i≠2)`） |
| 2 | `L111` / 4 阶的 `L` | |
| 3 | `L211` | 仅 6 阶 |
| 4 | `L311` | 仅 6 阶 |
| 5 | `S6` | 同时充当 `S6eta`；仅 6 阶 |
| 6 | `R` | |

**没有"常数 1"这一项**——逐类核对下来，每个*被使用*的项三项恰好落在三个轴上
（cls 1/2/3/4 的 `sp`/`n1`/`n2` 就是三根轴）。只有**未使用**的项需要一个零基，
否则求和会多出 `项数×1`：验证时用常数 1 恰好错 **+3.0**（三个空位各 +1）。

每项需要 `(kind, e)` 与"值 or 导数"两个槽。逐原子表：

```
Cs2Basis { float v[7][3][2]; float d[7][3][2]; }   // 42 floats = 168 B
```

`v[k][a][e] = f_k(e ? 1−t_a : t_a)`，`d` 为对 `t_a` 的导数（反射的 −1 已并入）。

**填充是分支无关的**：每种基都是 `t` 的 ≤5 次多项式，系数放在
`__constant__ c_poly[7][6]`（零基的系数全 0），每 lane 用 Horner 求一个
`(kind, axis, e)` 槽位——**同一条指令流**，只是系数不同。

42 个槽位 / 32 lane = **2 轮**。

### 4.2 逐节点索引表（静态，一次上传）

```
__constant__ unsigned char c_cs2_terms[2][88][4][3];   // [order][node][term][axis]
                                                        // 低 3 位 = kind，第 3 位 = e
```

- 2 个阶数 × 88 节点 × 4 项 × 3 轴 = 2112 B（每节点 12 B）。
- 由 `sog_gpu_create` 从 `c_nodes4s` / `c_nodes6s` **在 host 侧**分类生成，
  `cudaMemcpyToSymbol` 上传（一次性，不进图捕获）。
- 未用项写成 `kind = 0`（**零基**），值与其三个导数都是 0。

### 4.3 缩并（无分支）

```c
// 每个节点：
for (int t = 0; t < 4; ++t) {
  const int ix = c_cs2_terms[ord][n][t][0], iy = ..., iz = ...;
  const float ax = tab->v[ix&7][0][(ix>>3)&1], ...;
  w  += ax*ay*az;
  gx += tab->d[ix&7][0][(ix>>3)&1]*ay*az;
  gy += ax*tab->d[iy&7][1][(iy>>3)&1]*az;
  gz += ax*ay*tab->d[iz&7][2][(iz>>3)&1];
}
```

每节点 12 次 shared 读 + ~20 次乘加，**零分支**。
常数项的 `d` 恒 0，不需要特判。

### 4.4 两阶段（块内）

8 条 warp 各自一个原子 → 8 张表。**由全块 256 线程一起填**
（`idx = threadIdx.x + 256·r`，3 轮覆盖 8×84=672 个槽），
`__syncthreads()`，再进入 warp-per-atom 缩并。

> 与现状的差别：现在是每 warp 用自己的 32 lane 填自己的表（3 轮/原子，
> 且带 `switch` 发散）；改后是全块均匀一轮到底，**发散消失**。

### 4.5 数据流（与 B-spline 三段式对齐）

| B-spline | midtown（改后） | 说明 |
|---|---|---|
| `node_stencils` | `k_midtown_frac`（已有） + **块内表填充** | 逐原子的分数坐标已经提出去了；这一步补上"逐原子一维表" |
| `spread_charges` | `k_spread_cubes2_warp_fx_packed`（保留） | 散布每原子只做 6 次多项式，打包方案已是最优，**不改** |
| `interpolate_owners` | `k_gather_cubes2_warp_r`（重写缩并段） | 张量积缩并 |

散布**不改**的理由：它已经用"6 lane × 1 多项式/原子"把表填充摊到 4 个原子，
换成通用四项式反而要填 84 项/原子（21 轮），得不偿失。

### 4.6 顺带修好的一件事：散布与收集的权重逐位一致

现状 `cs2_w6_tab`（散布）与 `cs2_wg6`（收集）是两条不同的代数路线，
同一个 nodel 算出的 `w` 有 ~1e-7 的差。改成通用四项式后，两者都用
`Σ_t A·B·C` 且项序相同 → **w 逐位一致**，算子的伴随性从"近似"变成"精确"
（对 NHC 能量守恒和响应力都有好处）。

## 5. 预期收益（诚实版）

| 项 | 预期 |
|---|---|
| gather 自身 | −20%~−40%（去分支 + 无发散）；0.71 → 0.45~0.55 ms @196608 |
| 端到端 | **−5%~−10%**（3.14 → 2.9~3.0 ms） |
| 精度 | **完全不变**（同一 `∇E_mesh`） |
| 小网格（12288） | 收益更明显（延迟隐藏差，指令数占比高） |

真正价值不在这些百分点，而在于：

1. **结构对齐**：两棵树、两个后端都是"稠密元数据 + 无分支缩并"，
   以后改一处不用再想另一处；
2. **ik 的前置条件**：ik 的收集段是"用纯权重插值 3 个梯度场"，
   恰好就是本设计的缩并段去掉 `d` 项——改造成本从"重写"变成"删几行"；
3. 去掉 5 路发散后，寄存器压力和指令 cache 都改善，`ncu` 上更容易看出真瓶颈。

## 6. A/B 与验收

1. **数值**：单测要求 gather 前后在**同一网格**上的 `w` 逐位一致（4.6 的收益），
   端到端力/能量差 < 1e-6（相对）。用 `refio.py` 那套参考输出比对。
2. **性能**：`nsys` 逐 kernel，比较 gather 前后；端到端 12288 / 196608 / 786432 三点。
3. **回归**：`test_long_range_sum.py`(50)、`test_mesh_backend.py`(4)、
   `common/dpmodel/test_long_range.py`(61) 全过。
4. **图捕获**：新表是 `__constant__` + `__shared__`，无新分配，
   CUDA graph 捕获不受影响（不需要新计划）。

## 7. 风险

- **`__constant__` 索引表的 lane 发散读**：32 lane 读 32 个不同字节 → constant
  cache 按地址序列化，最坏 32 次。**缓解**：把它放进 `__shared__`（2112 B/块，
  一次 `__syncthreads` 载入），或把每节点的 12 个索引打平成 `char4` 对齐读。
  **首选 `__shared__`**。
- 一维表 42 个槽位（168 B/原子），块内 shared `8×168 = 1.3 KB`，比现在的
  `8×60×4 = 1.9 KB` 还小；占用率不受影响（当前 48 regs / 6 KB smem）。
- 若 A/B 显示端到端 < 3%，本设计**不做**，只把 4.6 的"逐位一致"当成小修单独落地。
