# 力的精度：诊断与改造计划

## 0. 问题与假设

实测（`docs/GRID_FROM_ACCURACY.md` §0、`docs/MESH_ERROR_MODEL_AND_FORM_A.md` §4.6）：

| backend | 阶 | 能量 `p_E` | 力 `p_F` | 差 |
|---|---|---|---|---|
| bspline | 4 | 4.28 | 3.5 | −0.8 |
| bspline | 6 | 7.33 | 6.0 | −1.3 |
| midtown (CubeS₂) | 4 | 4.41 | 3.0 | −1.4 |
| midtown (CubeS₂) | 6 | 6.60 | 5.0 | −1.6 |

**力总是比能量掉一阶多**。当前的力是**权重微分**（weight differentiation，即对上式
`φ = Σ_k w_k(r) φ_k` 里的插值权重求解析导，`cs2_wg6` 那条反向模式多项式），
而不是 **ik 微分**（`F = IFFT(i k · Ĝ ρ̂)` 之后再插值）。

假设 H：掉的那一阶来自 **CubeS₂ 的窗口是 `C⁰`**——对它求导得到不连续的力场；
ik 微分绕开对窗口求导，力的阶应当回到 `p_E`。

若 H 成立，收益是**格点数**：1e-4 力精度下 CubeS₂-6 现在要 `Δ/σ=0.481`；
若 `p_F` 回到 6.5–6.6、常数接近能量的 0.074–0.12，则 `Δ/σ≈0.34–0.37`，
**每条轴粗 1.3–1.4×，格点少 2.3–2.8 倍（三维 ≈ 6–13×）**。

但 H 有一个必须先排除的替代解释：

> **H′：损失是本征的。** 网格能量 `E_mesh(r)` 与真能量差 `O(Δ^{2ν})`，
> 它的*梯度*天生差 `O(Δ^{2ν−1})`——即使精确求导也一样。ik 之所以更好，
> 是因为它算的不是 `∇E_mesh`，而是"精确势场在网格上取值后再插值"的梯度，
> 代价是 **力不再严格等于 `−∇E_mesh`**（NVE 能量漂移）。

所以计划的第一件事不是改代码，而是**用脚本把 H 和 H′ 分开**。

---

## 1. 诊断（Phase 1）— 三个脚本，不动 C++

### 1.1 一致性检查：解析力是否就是 `∇E_mesh`？

用现有算子对每个坐标做中心差分（`h = 1e-4 Å`），比较
`F_ad`（算子返回的力）与 `F_fd = −(E(r+h) − E(r−h))/2h`：

```
rms(F_ad − F_fd) / rms(F_ad)  ≪ 1   →  我们的力 = ∇E_mesh（无实现 bug）
否则                                →  先修 bug（见 1.4），本计划暂停
```

成本：64 原子 × 3 方向 × 2 = 384 次 energy-only 调用，`N=64` 下几十秒。

### 1.2 决定性实验：ik vs 权重微分的力误差阶

用**纯 PyTorch 原型**（`sog/src/sog/module/cubes2_spline.py` 已有可微的
`cubes2_weight_6/4`，直接 autograd 就得到权重微分的力）：

```
原型管线:  ρ = scatter(q·w(t))  →  ρ̂ = rfftn(ρ)  →  φ̂ = G·ρ̂
           φ  = irfftn(φ̂)                                    (能量/vpot)
           W  = 权重微分力:  F_i = −q_i Σ_k (∂w_k/∂r_i) φ_k   (autograd)
           IK = ik 微分力:   u_a = irfftn(i k_a φ̂),  F_i = −q_i Σ_k w_k u_a[k]
参考解:    直接 k-sum（与能量表同一份，`direct_k_sum`）
扫描:      Δ/σ ∈ [0.15, 1.0]，同一 32 个 64 原子构型
输出:      两条力误差曲线的 p_F
```

判据：

- `p_ik ≈ p_E`（6.5±0.5 @ 6 阶，4.3±0.5 @ 4 阶）→ **H 成立，进入 Phase 3**；
- `p_ik ≈ p_ad`（5.0 / 3.0）→ **H 不成立**，力的一阶损失是本征的，
  改微分方式没用；退回 Phase 5 的替代路线（见 §6）；
- 介于两者之间 → 记录实际指数，收益按实测重算后再决定。

成本：一个脚本 + 一次扫描，半天。

### 1.3 窗口光滑性探针（解释性，不阻塞）

对 CubeS₂ 4/6 阶，沿一条轴扫 `t ∈ [0,1]`（跨 3 个胞），画出 `w(t)` 与 `∂w/∂x(t)`：
数一数 `∂w` 在胞界处跳变的大小，以及跳变随 `Δ` 的缩放。对应论文 Table I 的
`C⁰`（6 阶）/`C²`（4 阶）标注，用来解释为什么两个阶数的力都掉一阶。

### 1.4 若 1.1 不一致：先查三处已知易错点

1. `k_kspace_h` 的 `gee` / `gvv` 混淆（`sog_gpu.cu` 里 `sp[j].x = scaleinv*g.x*rr`
   用的是 `g.x = gee`，virial 用 `g.y = gv`）；
2. 力只对 `φ` 求导、没算 `∂M/∂r`（传播矩阵随位置的导数）这一项是否真的为零；
3. 三斜 / 正交的 `1/L` vs `1/L_eff` 标度（`sog_gpu_solve_f` 里两处 `1.0/lx`）。

## 2. 决策门（Phase 2）

只有同时满足才动 C++：

- 1.1 一致性通过（`rms(F_ad−F_fd)/rms(F_ad) < 1e-3`）；
- 1.2 给出 `p_ik ≥ p_E − 0.5`；
- 1.2 的等精度收益 ≥ 3× 格点（否则不值 +25% 的 FFT 成本）。

## 3. 实现（Phase 3）— ik 微分路径

只改 A 链的图内算子，B 链（LAMMPS）在 Phase 5 跟进。

### 3.1 `source/op/pt/long_range/midtown/sog_gpu.cu`

| 位置 | 改动 |
|---|---|
| `SogGpuState` | 新增 `float *f_grad_r[3]`（3 × ngrid 实网格）、`size_t cap_grad`；`sog_gpu_destroy` 释放 |
| `ensure_*` | `ensure_grad(s)`：按 ngrid 分配 3 个实网格；复用已有的 `f_spec`（φ̂）与一块 complex scratch |
| 新 kernel `k_grad_spec` | 逐模写 `g_a = i k_a φ̂`，与 `k_kspace_h` 同一次遍历内完成三个分量（`kx,ky,kz` 已在寄存器里）；Nyquist 与零模已由现有 `weightless` 判据置零 |
| `f_plan_c2r` | 复用同一个 1-batch C2R 计划，对 3 个分量各调一次（见 §3.3 的内存权衡） |
| 新 kernel `k_pack_grad` | 把 3 个 C2R 输出打包成**交错**的 `float3` 网格（每格点 3 个相邻 float）。交错是必须的：gather 对每个模板点只需一次 12 B 访问（落在同一个 32 B sector 内），否则三个分量各自散读，sector 数 ×3 |
| `k_gather_cubes2_warp_r` | 力改为 `dtx = Σ_k w_k · u.x[k]`（**只读权重，不求导**），vpot 与现在一致。逐节点的梯度多项式消失，但每点读取从 4 B 变 12 B，二者大致相抵——净效果要实测，不能假设变快 |
| `sog_gpu_compute_core` | CubeS₂ 分支：`k_kspace_h` 之后 → 3 × (k_grad_spec + C2R) → gather(ik) |
| 自作用项 | 无需改：自能 `½q²g(0)` 是常数，位置导数为零 |

开关：`SOG_MIDTOWN_FORCE_IK=1` 启用，默认**先关**，A/B 完成后翻转。

### 3.2 `source/op/pt/long_range/mesh_sum.cu`（B-spline，第二批）

`interpolate_owners` 同样用预计算斜率（权重微分）。它没掉阶（`p_F = 6.0 = 阶`），
但常数比能量差 2×。等 CubeS₂ 的结论出来后再决定是否一并改，改法相同，
开关 `SOG_BSPLINE_FORCE_IK`。

### 3.3 内存与成本

以 250³（16.6 M 格点）为例：

| 方案 | 额外显存 | 额外变换 |
|---|---|---|
格点 250³ = 15.6 M：实网格 62.5 MB，complex 谱 125 MB。

| 方案 | 额外显存 | 额外变换 |
|---|---|---|
| A：3 实网格（交错）+ 1 complex scratch，顺序 3 次 C2R | 187.5 + 125 = **312 MB** | 3 × C2R ≈ **+0.85 ms** |
| B：交错网格 + 3 complex，batch=3 一次 C2R | 187.5 + 375 = 562 MB | 3 × C2R，少 2 次 launch |

取 A。该尺寸现在算子占 ~512 MB，改后 ~825 MB；12288 原子（98³）只多 ~30 MB。
额外变换是现在 3.14 ms 调用的 +27%——**只要决策门要求 ≥3× 格点收益，这笔账就是赚的**。

再加一次 `k_pack_grad` 打包（读写 187 MB，约 +0.1–0.2 ms）。
gather 侧省的梯度多项式与多读的 8 B/格点相抵，净变化需实测（上一轮已证明
gather 的逐节点算术不是瓶颈，所以**不要指望它变快**）。

### 3.4 图捕获与缓存

新增的 3 次变换必须能被 CUDA graph 捕获：与现有 `f_plan_r2c/c2r` 同生命周期
（已 `cufftSetAutoAllocation(0)` + 固定 work area，满足捕获条件）；
`midtown_sum.cu` 的绿表缓存 key 不变。

## 4. 验收（Phase 4）

1. **阶**：力误差对 `Δ/σ` 的斜率 `p_F ∈ [p_E−0.5, p_E+0.5]`（32 构型，同一直接 k-sum）。
2. **一致性**：`rms(F_ik − F_ad)/rms(F_ik)` 记录在案（预期 O(Δ) 而不是 O(1)）。
3. **守恒**：NVE 下 10 ps 能量漂移，与当前 `F_ad` 对比。判据：漂移不放大 10×；
   若放大，**默认保持 `F_ad`，ik 作为可选加速档**，并在文档里写明这是一致性/精度的取舍。
4. **virial**：模求和 virial 不变；检查 `Σ F·r` 与模求和是否仍在噪声内一致
   （ik 力与模和 virial 不再严格自洽，需量化差值）。
5. **回归**：`test_long_range_sum.py`、`test_mesh_backend.py`、
   `common/dpmodel/test_long_range.py` 全过；与改前的 `F_ad` 在**同一网格**上
   差异应在 O(Δ) 量级（不是逐位相同，这点要写进测试注释）。

## 6. 若 H 不成立（ik 不改变阶）

按顺序尝试，每项都先用 1.2 的原型验证再进 C++：

1. **3D 显式 ik 高阶修正**：`F = IFFT(i k · Ĝ ρ̂)` 里把 `Ĝ` 换成
   `Ĝ · sinc 修正`，补偿窗口导数的最低价项。
2. **换样条**：CubeS₂-4 标注 `C²`，若实测 `p_F` 明显高于 3，说明"连续性类别决定掉阶"
   成立，可考虑用更高连续性的节点几何（论文的 `ξ` 备选值 `2/√15` 不改变连续性，
   但 QuadS 的可分离窗口更光滑——需先量 QuadS-6 的力阶）。
3. **提高网格分辨率换精度**：即当前规则，只做常数收紧（成本不变）。
4. **两套网格**：能量/长程用一套、力用更细的一套——只在分析场景可接受，MD 里不现实。
